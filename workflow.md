# Порядок роботи

Як робота проходить шлях від ідеї до коміту в цьому репозиторії, який скіл запускати і з якої
папки. Для людей і для агентів.

## 1. Де відкривати сесію

Папка, у якій ви відкриваєте Claude Code, визначає, куди потраплять спека й тікети.

| Робота змінює… | Відкрийте сесію в | Спека й тікети потрапляють у |
|---|---|---|
| фічу для користувача (більше одного підпроєкту) | корені репозиторію | `.scratch/<feature>/` |
| контракт: `docs/api.md`, `docs/cv-statuses.md`, `shared/`, терміни продукту | корені репозиторію | `.scratch/<feature>/` |
| лише внутрішню частину backend | `backend/` | `backend/.scratch/<feature>/` |
| лише внутрішню частину frontend | `frontend/` | `frontend/.scratch/<feature>/` |

Не впевнені → корінь. Якщо робота в підпроєкті потребує зміни контракту, зупиніться й створіть
тікет у корені, який її блокує.

### Корінь і підпроєкт: хто що веде

Корінь — це «менеджер»: продуктова спека (*що* робить фіча для користувача) і тікети на контракт
(`shared`, `docs/api.md`) та інші підпроєкти. Підпроєкт веде власну спеку й тікети (*як* це
зробити) і посилається на корінь:

- спека підпроєкту називає кореневу спеку в рядку `Sources:`;
- тікет підпроєкту, що реалізує кореневий тікет, має рядок `Implements:` зі шляхом до нього;
- тікет підпроєкту чекає на кореневий через `Blocked by:` зі шляхом від кореня репозиторію;
- коли тікети підпроєкту перебрали кореневий тікет, той отримує `Status: moved` і рядок
  `Moved to:` з їхніми шляхами — жодна робота не має двох живих тікетів.

Виняток: якщо контракт уже готовий і інший підпроєкт уже працює за ним, фіча, яка лишилася одному
підпроєкту, починається одразу в ньому, без кореневої спеки й тікетів. Спека підпроєкту тоді
називає в `Sources:` сам контракт (`docs/api.md`, `docs/cv-statuses.md`, `shared/`) і журнал
рішень кореня. Так робиться серверна частина: `backend/`, `/grill-with-docs` → `/to-spec` →
`/to-tickets` → `/implement`, джерела — контракт, `.scratch/backend/decisions.md` і моки
фронтенда (`frontend/src/mocks`) як зразок поведінки сервера.

## 2. Послідовність

```
/grill-with-docs ──▶ /to-spec ──▶ /to-tickets ──▶ /implement (по одному на тікет) ──▶ merge
└──────────── одна сесія, без /compact і /clear ─────────────┘   └── щоразу нова сесія ──┘
```

1. **Уточнити** — `/grill-with-docs <тема>`. Claude ставить пронумеровані питання раундами (Q1,
   Q2…) і до кожного дає рекомендовану відповідь; відповідайте за номерами (`Q1 — так`,
   `Q2 — ні, бо…`). Терміни потрапляють у `GLOSSARY.md`, рішення — в ADR. Закінчується, коли
   відкритих питань не лишилося і ви це підтвердили.
2. **Спека** — `/to-spec`. Пише `spec.md` з розмови; нових питань не ставить.
3. **Тікети** — `/to-tickets`. Ділить спеку на тікети з рядками `Blocked by:` і просить вас
   погодити поділ. Тікети в корені мають рядок `Package:` — зазвичай `shared` → `backend` →
   `frontend`.
4. **Реалізація** — для кожного розблокованого тікета, у **новій** сесії:
   ```sh
   git switch main && git switch -c feat/<short-desc>
   ```
   потім `/implement <шлях до тікета>`. Він працює через тести (`/tdd`), наприкінці запускає
   `/code-review` і комітить у поточну гілку — тому ніколи не запускайте його на `main`.
5. **Завершення** — перевірте коміти, потім `git switch main && git merge --ff-only <branch>` і
   `git branch -d <branch>` (див. *Git & commits* у `CLAUDE.md`). Тікет отримує `Status: done`.

`backend/` і `frontend/` — git-сабмодулі з власними репозиторіями: гілки й коміти тікета робляться
всередині сабмодуля, після злиття в його `main` у корені комітиться новий вказівник
(`git add backend`). Оновити всі три репозиторії до останнього `main`: `pnpm pull`.

Невелика зміна, що вміщується в одну сесію → кроки 2–3 можна пропустити: `/grill-with-docs`, потім
`/implement`.

## 3. Команди

Команди з ✋ запускаються лише тоді, коли ви їх набираєте; решту Claude може запустити й сам.

| Команда | Для чого |
|---|---|
| `/grill-with-docs <тема>` ✋ | уточнити план; пише глосарій і ADR |
| `/to-spec` ✋ | перетворити розмову на `spec.md` |
| `/to-tickets` ✋ | поділити спеку на тікети з блокерами |
| `/implement <тікет>` ✋ | реалізувати тікет: TDD → код-рев'ю → коміт |
| `/tdd` | red-green-refactor, по одному зрізу |
| `/code-review <since>` | рев'ю гілки на відповідність стандартам репозиторію та спеці |
| `/diagnosing-bugs` | складний баг або регресія: спершу відтворити, потім виправити з регресійним тестом |
| `/prototype` | одноразовий код, щоб відповісти на одне питання дизайну; відповідь зберегти, код видалити |
| `/research <питання>` | фоновий агент читає першоджерела й лишає Markdown-нотатку |
| `/grill-me` ✋ | те саме інтерв'ю, нічого не записує |
| `/wayfinder` ✋ | робота, що не вміщується в одну сесію: карта тікетів-рішень |
| `/triage` ✋ | перетворити зовнішні баги й запити на готові тікети |
| `/improve-codebase-architecture` ✋ | знайти модулі, які варто поглибити (HTML-звіт) |
| `/handoff` ✋ | стиснути сесію у файл, щоб продовжити в новій |
| `/ask-matt` ✋ | не знаєте, яка команда підходить |

## 4. Гігієна контексту

- Grilling, спека й тікети — в **одній** сесії, без `/compact` і `/clear`, доки не завершено `/to-tickets`.
- Кожен `/implement` — у **новій** сесії.
- Сесія наближається до ~120k токенів → `/handoff`, відкрийте нову сесію й вкажіть їй файл handoff.

## 5. Що де лежить

| Що | Де |
|---|---|
| Правила й команди підпроєкту | `<папка>/CLAUDE.md` (кореневий діє всюди) |
| Контракт між підпроєктами | `docs/api.md`, `docs/cv-statuses.md`, `shared/` |
| Терміни продукту | `shared/GLOSSARY.md`; карта всіх глосаріїв: `GLOSSARY-MAP.md` |
| Терміни підпроєкту | `backend/GLOSSARY.md`, `frontend/GLOSSARY.md` |
| Рішення | `docs/adr/` (для всієї системи), `<підпроєкт>/docs/adr/` (локальні) |
| Спеки й тікети | `.scratch/`, `backend/.scratch/`, `frontend/.scratch/` |
| Налаштування скілів | `docs/agents/` (+ `<підпроєкт>/docs/agents/issue-tracker.md`) |

Глосарії, папки ADR і `.scratch/` створюються, коли в них уперше щось записують.

## 6. Приклад

```
# сесія в корені репозиторію
/grill-with-docs каркас backend і shared: GET /api/health, postgres + redis,
                 міграції Drizzle, образ backend, весь стек через docker compose up
… відповідаєте на раунди …
/to-spec
/to-tickets          → .scratch/backend-scaffold/issues/01-shared-package.md, 02-…, 03-…

# нова сесія, корінь репозиторію
git switch main && git switch -c build/shared-scaffold
/implement .scratch/backend-scaffold/issues/01-shared-package.md
```
